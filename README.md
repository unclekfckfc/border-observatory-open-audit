## 一句话：为什么公开

我们的项目笔记里写着一句：

> **「自证有上限，他证只能来自真实的人。」**

过去一年多，我们搭了一套"可验证诚实"的机制：验讫章、逐字摘录、独立信源数、更正档案。但它有一个致命缺陷——**这套机制只能自己证明自己**。

而自证是会犯错的，而且**两个方向都犯过**：

- **漏错**：把同一篇通稿的 4 家转载，误判成「4 家独立交叉源」（实际是 1 个）。
- **造错**：误伤了两条本来正确的条目，指控它们"不该盖绿章"，后来核验发现是**我们引用的规则是我们自己写的**，于是自我撤回。

所以这次我们把**方法论、数据、缺口、错误**全部公开，并且**公开邀请你来找错**。

## 怎么挑错（这是本仓库存在的目的）

**任何一条都欢迎，尤其是这三种：**

1. **某条信号的标注是错的**——章位、来源、摘录、独立源数，任何一项。
2. **方法论里某条规则是错的**——比如"同一通稿 = 1 个来源"是否太严/太松。
3. **标准 CTL 漏了关键情况**——哪些场景这套标注会失效。

**去哪里挑**：
- **直接回信**：`xvpp2806@agent.qq.com` —— **当前唯一确认可用的通道**
- 提 issue（本仓库）——⚠️ **截至 2026-10-14 仓库尚未建立**，见 [PUBLISH.md](PUBLISH.md)。我们不会把一个点不开的入口挂在这里冒充可用。
- 完整流程、我们的处理承诺与「不承诺什么」：[CONTRIBUTING.md](CONTRIBUTING.md)

**我们承诺**：
- 确认是错的 → 记入更正档案（`append-only`，只追加不删改），**含改前原值**
- 同时把 `corrected` 标志位落库并推到用户可见处（**只改文案不算更正**，这条是我们用真事换来的）
- 不是错的 → 也如实说明为什么，不敷衍

> **被你挑出一个我们没发现的真错误，比我们自己再写一百条更正都有价值。**

## 三层公开架构（母版唯一）

```
① 本地母版  deliverables/open-audit/   ← 唯一真相源
      ↓ 同步
② GitHub 公开仓库                        ← 技术受众 / commit 历史 = 不可篡改的更正时间线
      ↓ 同步
③ 线上公开审计页                          ← 决策受众 / 可视化
```

**纪律**：母版唯一，其余两处从它同步生成。**绝不三处各写各的**（我们曾踩过"两套真相源"的坑：站内说 A、助手说 B）。

## 边界（我们不是什么）

- **CTL 标准不是法律意见**，不保证满足任一辖区要求
- **我们不是审核系统**：不产生真实审核记录，只做展示层标注
- **不替代任何行政审批**（新闻资质、ICP、数据跨境等均未定性）
- **AI 判定是文本模式匹配，不是内容检测**
- **展示层标注可被移除**，不得当作不可篡改的证据使用
